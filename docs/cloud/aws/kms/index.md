# KMS

AWS Key Management Service — key creation, encryption, access control, and audit.
## Key Types

| Key Type | Description |
|---|---|
| AWS managed key | Created by AWS for a service (e.g., `aws/s3`) — no cost, limited control |
| Customer managed key (CMK) | Created by you — full control, rotation, policy, $1/month |
| Data key | AES-256 key generated by KMS, encrypted by a CMK (envelope encryption) |
| Multi-region key | Same key material replicated across regions |

## Common CLI Commands

```bash
# List KMS keys
aws kms list-keys \
  --query 'Keys[*].KeyId' --output text

# Describe a key
aws kms describe-key --key-id <key-id-or-alias> \
  --query 'KeyMetadata.{ID:KeyId,State:KeyState,Rotation:KeyRotationStatus,Created:CreationDate}'

# List aliases
aws kms list-aliases --query 'Aliases[*].{Alias:AliasName,KeyId:TargetKeyId}' --output table

# Create a CMK
aws kms create-key \
  --description "Prod database encryption key" \
  --key-usage ENCRYPT_DECRYPT \
  --key-spec SYMMETRIC_DEFAULT

# Create alias
aws kms create-alias \
  --alias-name alias/prod-db \
  --target-key-id <key-id>

# Enable automatic rotation (annually — SYMMETRIC_DEFAULT only)
aws kms enable-key-rotation --key-id <key-id>

# Check rotation status
aws kms get-key-rotation-status --key-id <key-id>
```

## Encrypt and Decrypt (Testing)

```bash
# Encrypt a value (returns Base64-encoded ciphertext)
aws kms encrypt \
  --key-id alias/prod-db \
  --plaintext "secret-value" \
  --query 'CiphertextBlob' --output text > encrypted.b64

# Decrypt
aws kms decrypt \
  --ciphertext-blob fileb://<(base64 -d encrypted.b64) \
  --query 'Plaintext' --output text | base64 -d
```

## Key Policy Management

```bash
# Get current key policy
aws kms get-key-policy --key-id <key-id> --policy-name default

# Put a new key policy (replace default)
aws kms put-key-policy \
  --key-id <key-id> \
  --policy-name default \
  --policy file://key-policy.json
```

**Minimal key policy (allow IAM users/roles to use the key):**
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "Allow account root",
      "Effect": "Allow",
      "Principal": {"AWS": "arn:aws:iam::<account>:root"},
      "Action": "kms:*",
      "Resource": "*"
    },
    {
      "Sid": "Allow service role to use key",
      "Effect": "Allow",
      "Principal": {"AWS": "arn:aws:iam::<account>:role/AppRole"},
      "Action": ["kms:Decrypt","kms:GenerateDataKey"],
      "Resource": "*"
    }
  ]
}
```

## Audit with CloudTrail

CloudTrail logs all KMS API calls. Search for:
- `Decrypt` — who decrypted what, when
- `GenerateDataKey` — service using the key for envelope encryption
- `DisableKey` / `ScheduleKeyDeletion` — destructive operations

```bash
aws cloudtrail lookup-events \
  --lookup-attributes AttributeKey=EventName,AttributeValue=DisableKey \
  --query 'Events[*].{Time:EventTime,User:Username,KeyId:Resources[0].ResourceName}'
```

## Troubleshooting

| Symptom | Check | Action |
|---|---|---|
| `KMSAccessDeniedException` | IAM + key policy | Both IAM policy AND key policy must grant access |
| Key pending deletion | `KeyState: PendingDeletion` | Cancel deletion: `aws kms cancel-key-deletion --key-id <key-id>` |
| Can't rotate key | Key type | Only SYMMETRIC_DEFAULT CMKs support automatic rotation |
| Cross-account access denied | Key policy | Key policy must explicitly allow the external account/role |
