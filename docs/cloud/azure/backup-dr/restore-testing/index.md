## Restore a VM to a New VM (Full Restore)

```bash
# Restore disks and reconstruct a new VM from the restored template
az backup restore restore-disks \
  --resource-group <rg> \
  --vault-name <vault-name> \
  --container-name <container-name> \
  --item-name <vm-name> \
  --rp-name <recovery-point-id> \
  --storage-account <staging-storage-account-name> \
  --target-resource-group <target-rg>

# After restore-disks completes, deploy the VM from the restored template JSON
# (The template is written to the staging storage account by the restore job)
az deployment group create \
  --resource-group <target-rg> \
  --template-uri "<sas-url-to-template.json>"
```

!!! warning "Common errors"
    **`The specified recovery point 'rp-20240115T143022Z' does not exist or is not accessible.`** — Verify the recovery point ID with `az backup recoverypoint list --resource-group <rg> --vault-name <vault-name> --container-name <container-name> --item-name <vm-name>` and use a valid point.
    **`The storage account '<staging-storage-account-name>' does not exist or you do not have access to it.`** — Ensure the staging storage account exists in the same subscription and your user has Storage Blob Data Contributor role assigned.
    **`Template deployment failed: InvalidTemplate - The template is invalid.`** — Verify the SAS URL is still valid (not expired) and points to the correct template JSON file generated by the restore-disks operation.

## Restore to Original Location (Overwrite Existing VM)

This is a destructive operation. Only use after confirming the source VM is deallocated.

```bash
# Deallocate source VM before in-place restore
az vm deallocate \
  --resource-group <rg> \
  --name <vm-name>

# Restore to original location
az backup restore restore-disks \
  --resource-group <rg> \
  --vault-name <vault-name> \
  --container-name <container-name> \
  --item-name <vm-name> \
  --rp-name <recovery-point-id> \
  --storage-account <staging-storage-account-name> \
  --restore-to-staging-storage-account false
```

!!! warning "Common errors"
    **`BadRequest: The VM 'prod-web-01' must be deallocated before performing an in-place restore.`** — Run `az vm deallocate --resource-group <rg> --name <vm-name>` first and wait for completion.
    **`ResourceNotFound: Recovery point '<recovery-point-id>' not found in vault '<vault-name>'.`** — Verify the recovery point ID exists by running `az backup recoverypoint list --resource-group <rg> --vault-name <vault-name> --container-name <container-name> --item-name <vm-name>`.
    **`InvalidStorageAccount: Staging storage account '<staging-storage-account-name>' does not exist or is inaccessible.`** — Ensure the storage account exists in the same region and subscription, and the vault has the necessary permissions.

## File-Level Recovery

Azure Backup supports mounting a recovery point to the running VM for file-level browsing.

```bash
# Get a restore script for file-level recovery (script is downloaded from portal or REST)
# Use the portal "File Recovery" blade to generate and download the script
# Script is executed on the target VM to mount the backup snapshot as a local disk

# After file recovery, unmount using the cleanup script or portal
```

| Recovery Method | Use Case | Data Loss Risk |
|---|---|---|
| Disk restore to alternate location | Test validation, safe DR drill | None to source |
| Full VM restore (new VM) | Environment rebuild, cloning | None to source |
| Original location restore | Corruption recovery | Overwrites live disks |
| File-level recovery | Single file/folder recovery | None to source |

## Validating a Restored VM

```bash
# Confirm restored VM is in running state
az vm show \
  --resource-group <staging-rg> \
  --name <restored-vm-name> \
  --show-details \
  --query "powerState" --output tsv

# Check boot diagnostics for startup errors
az vm boot-diagnostics get-boot-log \
  --resource-group <staging-rg> \
  --name <restored-vm-name>

# Run a command on the restored VM to verify OS health
az vm run-command invoke \
  --resource-group <staging-rg> \
  --name <restored-vm-name> \
  --command-id RunShellScript \
  --scripts "df -h && systemctl is-active <service-name>"
```

!!! warning "Common errors"
    **`The resource 'Microsoft.Compute/virtualMachines/<restored-vm-name>' under resource group '<staging-rg>' was not found.`** — Verify the restored VM name and resource group name match exactly, checking for typos or case sensitivity.
    
    **`InvalidTemplateDeploymentProperties: Boot diagnostics is not enabled on this VM.`** — Enable boot diagnostics on the VM before attempting to retrieve logs using `az vm boot-diagnostics enable`.
    
    **`The command failed with an exit code of 1 on the VM.`** — Verify the service name in the systemctl command exists on the restored VM and that the VM has network connectivity to execute the command.
