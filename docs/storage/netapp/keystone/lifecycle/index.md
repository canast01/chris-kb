# NetApp Keystone Lifecycle

## Subscription Terms

- Typical Keystone subscription terms are 1 to 3 years; longer terms typically offer more favorable per-TB pricing
- Renewal discussions should begin at least 6 months before subscription expiry to allow time for capacity planning, negotiation, and order processing
- Committed capacity can be increased mid-term via a subscription amendment; committed capacity cannot be decreased until the next term
- If requirements change significantly mid-term, engage the Keystone Success Manager — NetApp has mechanisms for partial amendments or service level changes in certain circumstances

## True-Up Process

- The Keystone Collector reports consumption telemetry on a continuous basis; NetApp aggregates this into a monthly consumption report
- Monthly reports are visible in the BlueXP Keystone dashboard and digital wallet before the invoice is generated — review the report before month-end to identify unexpected burst
- The invoice reflects committed capacity (flat monthly charge) plus burst usage (higher per-TB rate for any consumption above committed)
- If the consumption report shows data that appears incorrect, raise a discrepancy with the Keystone Success Manager before the invoice is finalized

## Hardware Refresh

NetApp manages all hardware refresh within the Keystone subscription period. There is no customer capital expenditure for hardware replacement, upgrades, or end-of-life refreshes. NetApp determines refresh timing based on its own hardware lifecycle management. Customers receive advance notice of hardware refresh activities. Hardware refreshes include data migration to new hardware — NetApp coordinates and executes this with minimal customer disruption.

## Exit / Migration

- At subscription end, the customer is responsible for migrating data off the NetApp-managed infrastructure before the decommission date
- NetApp provides migration support as part of the exit process; engage the Keystone Success Manager and NetApp Professional Services at least 6 months before the planned exit date
- Identify target infrastructure (new Keystone term, alternative vendor, cloud) and begin data migration planning 6 months ahead
- Keystone hardware remains NetApp property and is removed by NetApp after decommission; ensure all data is migrated and confirmed before allowing hardware removal
- Plan for DNS, share, and application reconfiguration if moving to a different storage platform or naming structure
