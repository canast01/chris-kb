# FlashArray — Backup & Restore

> Backup configuration, restore procedures, and validation for Pure Storage FlashArray.

## Overview

FlashArray provides multiple data protection mechanisms:

- **Protection Groups (PGroups)** — consistent snapshots across volumes, hosts, or host groups with configurable schedules and async replication to a remote array
- **ActiveCluster Pods** — synchronous replication providing RPO=0 across two sites
- **SafeMode Snapshots** — immutable snapshots protected against admin deletion, requiring a dual-approval process via Pure Support

## Backup Configuration

Refer to the [Procedures — Protection Groups](../procedures/#protection-groups) section for configuration commands.

Key steps:

1. Create a protection group per application: `purepgroup create <pg_name>`
2. Add volumes to the protection group
3. Configure a snapshot schedule (frequency, retention)
4. Configure a replication target if async replication is required
5. Validate schedule is active: `purepgroup list --schedule`

## Restore Procedures

### Restore a Volume from a Protection Group Snapshot

```bash
# List available protection group snapshots
purepgroup listsnaps <pg_name>

# Copy a snapshot to a new volume (for validation before overwrite)
purevol copy <pg_name>.<snap_suffix>.<vol_name> restore-<vol_name>

# Overwrite the original volume with the snapshot (disruptive — disconnect hosts first)
purevol copy <pg_name>.<snap_suffix>.<vol_name> --overwrite <vol_name>
```

### Restore a Volume from a Volume Snapshot

```bash
# List snapshots for a specific volume
purevol list <vol_name>.*

# Restore by overwriting
purevol copy <vol_name>.<snap_suffix> --overwrite <vol_name>
```

### Recover a Destroyed Volume

Volumes remain in a destroyed (pending-eradication) state for 24 hours before being permanently deleted.

```bash
# List destroyed volumes
purevol list --pending

# Recover a destroyed volume
purevol recover <vol_name>
```

## Validation

After any restore:

- [ ] Rescan HBA on the host side and confirm volumes are visible
- [ ] Mount the filesystem and validate data integrity at the application layer
- [ ] Run `purealert list` — confirm no alerts generated by the restore activity
- [ ] Verify protection group schedule is still active: `purepgroup list --schedule`
- [ ] Document the restore in the change log with timestamp and outcome
